# ComfyUI-MinuteSaver ⏱

按**系统时间（精确到分钟）**自动分文件夹 / 命名保存**图像**与**视频**的 ComfyUI 自定义节点。

灵感来自 WAS Node Suite 的 `Image Save` 与 VideoHelperSuite 的 `VHS_VideoCombine`
里 `[time(%Y-%m-%d)]` 那套令牌写法 —— 但那个写法只能精确到「天」，而且必须手写
令牌。本节点把「时间」做成了两个独立开关：**文件夹上放什么时间**、**文件名上放什么时间**，
默认就精确到分钟。

## 安装

### 方式一：ComfyUI-Manager（推荐）

搜索 `MinuteSaver` → Install → 重启 ComfyUI。

### 方式二：手动 clone

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/zhang1san2feng3/ComfyUI-MinuteSaver.git
```

重启 ComfyUI 即可，**无需安装任何依赖**：

- 图像保存用 `Pillow`（ComfyUI 自带）
- 视频保存用 `ffmpeg`，按下面顺序自动查找：
  1. 环境变量 `FFMPEG_BINARY`
  2. 系统 `PATH` 里的 `ffmpeg`
  3. `imageio-ffmpeg` 内置的 ffmpeg（装了 VideoHelperSuite 就有）
  4. `C:\ffmpeg\bin\ffmpeg.exe`

  全都没找到时节点会给出明确报错，不会静默失败。

## 两个节点

分类：`MinuteSaver/时间保存`

| 节点 | 类名 | 输入 | 输出 |
|---|---|---|---|
| ⏱ 按时间保存图像 | `MinuteSaveImage` | `IMAGE` | `images` / `完整路径` / `文件夹` |
| ⏱ 按时间保存视频 | `MinuteSaveVideo` | `IMAGE`（+ 可选 `AUDIO`） | `完整路径` / `文件夹` |

图像节点会把 `IMAGE` 原样透传出去，所以可以插在流程中间继续接别的节点。

## 默认输出长什么样

ComfyUI 的 `output` 是**一级目录**（固定，节点只能写在它下面），所以节点只给一个
**「输出文件夹」** 字段，默认 `[time(%Y-%m-%d)]` = **当前日期**；类型靠**文件名前缀**区分。

图像（默认参数）：

```
ComfyUI/output/2026-09-06/Image_2026-09-06_16-13-45_0001.png
└─ 一级 ────┘└ 输出文件夹 ┘└前缀┘└─── 文件时间 ───┘└序号┘
```

视频（默认参数）：

```
ComfyUI/output/2026-09-06/Video_2026-09-06_16-13-45_00001.mp4
```

- **文件夹** = 日期，一天一个文件夹（`2026-09-06`）
- **前缀** = 类型 / 系列，图像默认 `Image`，视频默认 `Video`，也可以填 `我的系列示例` 这种
- **文件名时间** = 精确到秒，可以改成到分，也可以整个清空

文件名的时间**可以精确到分或秒，也可以整个不要**：

| 文件名时间格式 | 文件名 | 说明 |
|---|---|---|
| `[time(%Y-%m-%d_%H-%M-%S)]`（默认） | `Image_2026-09-06_16-13-45_0001.png` | 到秒 |
| `%H-%M-%S` | `Image_16-13-45_0001.png` | 只要时分秒 |
| `%H-%M` | `Image_16-13_0001.png` | 到分钟 |
| 清空 | `Image_0001.png` | 不带时间，只有前缀+序号 |

输出文件夹同样是「前缀 + 时间」的**自由组合**，也支持多级：

| 输出文件夹填什么 | 得到 |
|---|---|
| `[time(%Y-%m-%d)]`（默认） | `2026-09-06` |
| `%Y-%m-%d_%H-%M` | `2026-09-06_16-13`（每分钟一个文件夹） |
| `原始待查%Y-%m-%d` | `原始待查2026-09-06` |
| `%Y-%m-%dseedVR2放大` | `2026-09-06seedVR2放大` |
| `MiniMaxH3/%Y-%m-%d` | 多级目录 |
| 清空 | 直接写在 `output` 根目录 |

也可以只用 WAS 令牌写法：`原始待查[time(%Y-%m-%d)]` → `原始待查2026-09-06`。

## 时间格式怎么填

节点里的字段分两类，规则不一样，**记住这一条就够了**：

- **时间字段**（`输出文件夹`、`文件名时间格式`）→ 裸 `%` 直接解释
- **文字字段**（`文件名前缀`、`额外文件名`）→ 不解释裸 `%`，放时间要用 `[time(...)]` 令牌

### 时间字段（`输出文件夹` / `文件名时间格式`）

可以纯格式符，也可以「自定义文字 + 格式符」混着写：

| 写法 | 例子 | 渲染结果 |
|---|---|---|
| 纯格式符 | `%Y-%m-%d` | `2026-09-06` |
| 纯格式符 | `%H-%M-%S` | `16-13-45` |
| 文字 + 格式符 | `原始待查%Y-%m-%d` | `原始待查2026-09-06` |
| 格式符 + 文字 | `%Y-%m-%dseedVR2放大` | `2026-09-06seedVR2放大` |
| 令牌写法 | `[time(%Y-%m-%d)]` | `2026-09-06` |
| 令牌嵌文字 | `存档[time(%m-%d)]` | `存档09-06` |

### 文字字段（`文件名前缀` / `额外文件名`）

这两个字段是「你随便写的文字」，所以**绝不解释裸 `%`**——
写 `A%B` 就是 `A%B`，不会变成 `ASeptember`；写 `进度100%` 就是 `进度100%`。

要在这种字段里放时间，用令牌：

| 写法 | 例子 | 渲染结果 |
|---|---|---|
| 令牌 | `原始待查[time(%m-%d)]` | `原始待查09-06` |
| 令牌 | `我的系列示例[time(%Y%m%d)]` | `我的系列示例20260906` |
| 裸 `%` | `A%B` | `A%B`（原样保留） |

> 也就是说，从旧的 `Image Save` / `VHS_VideoCombine` 里复制过来的
> `[time(%Y-%m-%d)]` 可以直接粘进来用。

### 可用格式符（strftime）

`%Y` 年、`%m` 月、`%d` 日、`%H` 时、`%M` 分、`%S` 秒、`%j` 年内第几天、
`%W` 周数、`%p` AM/PM……

组合示例：`%Y%m%d` → `20260906`、`%Y%m%d_%H%M%S` → `20260906_161345`。

### 额外令牌（所有字段都能用）

| 令牌 | 含义 |
|---|---|
| `[time]` | Unix 时间戳（秒） |
| `[date]` | 等价 `[time(%Y-%m-%d)]` |
| `[hostname]` | 机器名 |
| `[user]` | 当前用户名 |

⚠️ **Windows 文件名不允许 `: * ? " < > |`**，会被自动替换成 `_`。
所以写「时:分」请用 `%H-%M`，**不要**用 `%H:%M`（会变成 `16_13`）。

## 常用自定义示例

三个地方都能塞你自己的文字，时间放哪、放什么都随你：

| 目标 | 输出文件夹 | 文件名前缀 | 文件名时间格式 | 结果（相对 `output/`） |
|---|---|---|---|---|
| 默认 | `[time(%Y-%m-%d)]` | `Image` | `[time(%Y-%m-%d_%H-%M-%S)]` | `2026-09-06/Image_2026-09-06_16-13-45_0001.png` |
| 只要日期文件夹+序号 | `%Y-%m-%d` | `Image` | *(清空)* | `2026-09-06/Image_0001.png` |
| 日期带中文后缀 | `%Y-%m-%d原始待查` | `Image` | *(清空)* | `2026-09-06原始待查/Image_0001.png` |
| 文字在时间前面 | `原始待查%Y-%m-%d` | `Image` | *(清空)* | `原始待查2026-09-06/Image_0001.png` |
| 每分钟一个文件夹 | `%Y-%m-%d_%H-%M` | `Image` | *(清空)* | `2026-09-06_16-13/Image_0001.png` |
| 系列名当文件夹 | `我的系列示例%Y-%m-%d` | `Video` | `%H-%M` | `我的系列示例2026-09-06/Video_16-13_00001.mp4` |
| 前缀带批次号（令牌） | `%Y-%m-%d` | `第3批[time(%m%d)]` | `%H-%M-%S` | `2026-09-06/第3批0906_16-13-45_0001.png` |
| 从别的节点接线传词 | `%Y-%m-%d` | `Image` + `额外文件名` 接字符串 | `%H-%M-%S` | `2026-09-06/Image_<接线内容>_16-13-45_0001.png` |

`额外文件名` 是**可选输入端口**，可以把任意文本节点（角色名、批次名、文件夹名）
接进来，会追加到前缀后面——文件名就完全由工作流动态生成了。

| 保存模式 | 文件夹名含时间 | 文件名含时间 | 结果示例（相对 `output/`） |
|---|---|---|---|

| `仅文件名` | ❌ | ✅ | `Image_2026-09-06_16-13-45_0001.png` |
| `仅文件夹` | ✅ | ❌ | `2026-09-06/Image_0001.png` |
| `都不加(固定名)` | ❌ | ❌ | `Image_0001.png` |

## 参数详解

### ⏱ 按时间保存图像 (MinuteSaveImage)

| 参数 | 默认 | 说明 |
|---|---|---|
| `images` | — | 要保存的图像，支持批次（batch 会逐张按序号存） |
| `保存模式` | `文件夹+文件名` | 见上一节 |
| `输出文件夹` | `[time(%Y-%m-%d)]` | 相对 `output` 的文件夹，默认=当前日期；可写「前缀+时间」如 `原始待查[time(%Y-%m-%d)]`，可多级，清空则写 `output` 根目录 |
| `文件名前缀` | `Image` | 自定义文字，区分类型/系列（视频节点默认 `Video`）。只认令牌：要放时间写 `原始待查[time(%m-%d)]` |
| `文件名时间格式` | `[time(%Y-%m-%d_%H-%M-%S)]` | 默认到秒；可改 `[time(%H-%M)]`，**清空则文件名不带时间** |
| `文件名分隔符` | `_` | 前缀与时间之间的连接符 |
| `文件名序号位数` | `4` | 补零位数，`0001` |
| `文件名序号起始` | `1` | 起始序号 |
| `图片格式` | `png` | `png` / `jpg` / `webp` |
| `质量` | `很高 (95)` | **下拉选择**：最高(100) / 很高(95) / 高(90) / 中(80) / 较低(60) / 最低·体积最小(30)。jpg·webp 是压缩质量；png 无损，该值换算成压缩级别 |
| `重名处理` | `按序号自动递增` | 见下方「重名处理」 |
| `嵌入工作流` | ✅ | 把 prompt / 工作流写进 PNG，拖回 ComfyUI 能还原 |
| `允许绝对路径` | ❌ | 勾选后「输出路径」写绝对路径时直接写到该磁盘目录 |
| `输出路径_覆盖`（可选） | 空 | 留空则用「输出文件夹」。填相对路径时追加在它之后；填绝对路径（需勾选上一项）则整体改写到该磁盘目录 |
| `额外文件名`（可选） | 空 | 接一个字符串，追加到文件名前缀后面（如接角色名 / 系列名） |

**重名处理**

| 选项 | 行为 |
|---|---|
| `按序号自动递增`（默认） | 已存在就往后找一个空号，**永不覆盖** |
| `直接覆盖` | 同名直接覆盖 |
| `允许重名(追加毫秒)` | 同名时追加毫秒时间戳，避免覆盖 |

### ⏱ 按时间保存视频 (MinuteSaveVideo)

| 参数 | 默认 | 说明 |
|---|---|---|
| `images` | — | 图像序列。**批次会自动串成一段视频**（N 张 = N 帧） |
| `帧率` | `24.0` | 写入视频的 fps |
| `视频格式` | `mp4 (h264)` | `mp4` / `mov` / `mkv`（h264）/ `webm`（vp9） |
| `CRF质量` | `默认·推荐 (19)` | **下拉选择**：视觉无损(16) / 高(18) / 默认·推荐(19) / 中(22) / 较小体积(26) / 最小体积(32) |
| `保存模式` | `文件夹+文件名` | 同上 |
| `输出文件夹` | `[time(%Y-%m-%d)]` | 同上，可写「前缀+时间」 |
| `文件名前缀` | `Video` | 自定义文字，默认 `Video`；也可填系列名「我的系列示例」（放时间用 `[time(...)]` 令牌） |
| `文件名时间格式` | `[time(%Y-%m-%d_%H-%M-%S)]` | 默认到秒；清空则 `前缀_序号` |
| `文件名序号位数` | `5` | `00001` |
| `文件名序号起始` | `1` | 起始序号 |
| `重名处理` | `按序号自动递增` | 同上 |
| `保存元数据` | ✅ | 把 prompt / 工作流写进视频容器元数据 |
| `允许绝对路径` | ❌ | 同上 |
| `audio`（可选） | — | 接 VAE 解码出的 `AUDIO`，会一起写进 mp4（AAC 192k） |
| `输出路径_覆盖`（可选） | 空 | 同上 |
| `额外文件名`（可选） | 空 | 同上 |

视频输出是 **YUV420P**，浏览器 / 手机 / 剪映通吃；
奇数宽高的输入会自动裁成偶数，不会出现编码失败。

## 常见用法与坑

**1. 日期文件夹 + 前缀（对应你原来的 `2026-09-05原始待查` 习惯）**

```
保存模式        = 文件夹+文件名
输出文件夹      = 原始待查%Y-%m-%d      ← 前缀 + 时间
文件名时间格式  = 清空                  ← 文件名不带时间
文件名前缀      = Image
```
→ `output/原始待查2026-09-06/Image_0001.png`

把「输出文件夹」改成 `%Y-%m-%d原始待查` 就是 `2026-09-06原始待查`，位置随便放。

**2. 想要「每一分钟一个文件夹」**

```
保存模式        = 文件夹+文件名
输出文件夹      = %Y-%m-%d_%H-%M
文件名时间格式  = 清空
文件名前缀      = Image
```
→ `output/2026-09-06_16-13/Image_0001.png`

**3. 想保留原来的系列命名**

「文件名前缀」填系列名，例如 `我的系列示例`，
再按需要把「文件名时间格式」清空：

→ `output/2026-09-06/我的系列示例_00896.mp4`

想再分一层就写进「输出文件夹」：`MiniMaxH3/%Y-%m-%d` → `output/MiniMaxH3/2026-09-06/…`

**4. 想彻底不按时间分目录**

「保存模式」选 `都不加(固定名)`，等于一个普通保存节点。

**5. 节点上的「上次保存路径」什么时候更新？**

执行完成后才会显示真实路径。因为路径里的时间是按**执行那一刻**的系统时间算的，
所以在画布上实时预览反而会骗人，这里刻意不做实时推算。
点「📂 复制上次路径」可以把结果复制到剪贴板。

**6. 视频节点报「找不到 ffmpeg」**

装一个 ffmpeg 加进 PATH，或设置环境变量 `FFMPEG_BINARY` 指向 `ffmpeg.exe`；
装了 VideoHelperSuite 的话会自动用它的内置 ffmpeg。

**7. 文件名里想带 `:`**

做不到，Windows 不允许。用 `-` 代替。

**8. 序号会不会撞？**

`按序号自动递增` 模式下，每次保存都会先看目录里已有什么文件，
从起始序号往后找第一个空位，所以**同一分钟内连续出图是 0001、0002、0003…**，
不会覆盖已有文件。跨分钟时文件名换了，序号自然从 1 重新开始。

**9. 报 `WinError 206 文件名或扩展名太长` 怎么办？**

这是 Windows 的两个硬限制，节点都已经做了自动兜底，正常情况下你不需要管：

| 限制 | 上限 | 节点怎么处理 |
|---|---|---|
| 命令行长度（CreateProcess） | 约 32767 字符 | 工作流元数据太长时**不再塞进 ffmpeg 命令行**，改写成视频旁边的 json |
| 单条路径长度（MAX_PATH） | 260 字符 | 文件名主干 / 文件夹路径过长时**自动截断 + 8 位哈希尾巴** |

所以**超大工作流**（例如 MiniMax H3 那种提示词好几万字的）保存视频时，
你会看到视频旁边多出两个文件：

```
Video_2026-09-06_16-13-45_00001.mp4
Video_2026-09-06_16-13-45_00001.mp4.prompt.json      ← 完整 prompt
Video_2026-09-06_16-13-45_00001.mp4.workflow.json    ← 完整工作流
```

这是 ComfyUI 生态的惯例，拖回 ComfyUI 一样能还原工作流。

如果确实不想要这两个 json，把「保存元数据」关掉即可——
视频照常保存，只是不带工作流信息。

**10. 文件名太长会怎样？**

不会失败。超过长度上限时会保留头部 + 哈希尾巴，例如：:

```
超长前缀超长前缀超长前缀..._a1b2c3d4_0001.png
```

哈希保证两个不同的长名字不会被截断成同一个文件。

## 自检

**第一层：不启动 ComfyUI 也能跑**（会用你的 Python 真的生成 png/jpg/webp 和一个 mp4）：

```bash
python selftest.py
```

秋叶整合包环境里用：

```bash
E:\ComfyUI-aki-v1.6\python\python.exe selftest.py
```

**第二层：对运行中的 ComfyUI 实跑一次**（ComfyUI 需已启动）：

```bash
python apitest.py 6288      # 端口按你的实际启动参数改
```

它会通过 `/prompt` 真实排队执行两个节点，校验：文件夹名、文件名序号、
同一秒内重复运行不覆盖、mp4 可解码、奇数宽高自动裁剪等。
两个脚本最后都会打印 `失败项: 0` 才算通过。
